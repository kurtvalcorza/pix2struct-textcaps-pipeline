#### Description

`google/pix2struct-textcaps-base` is the Transformers-format release of the Pix2Struct *base* model fine-tuned on TextCaps, from "Pix2Struct: Screenshot Parsing as Pretraining for Visual Language Understanding" (Lee et al., arXiv:2210.03347), converted from the T5X checkpoints by the Hugging Face team and pinned here to revision `61bee0d7e2378e601b68f853ceee4f7cf99f1b88` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `Pix2StructForConditionalGeneration`: a 12-layer ViT-style image encoder (hidden size 768, 12 heads, feed-forward width 2048, 16×16 patches with learned row/column position embeddings over a variable-resolution input of up to 4096 patch positions) and a 12-layer T5-style text decoder (hidden size 768, 12 heads of width 64, vocabulary 50,244, `max_length` 20) — 282M parameters in the 1.13 GB float32 `model.safetensors`. The model was pretrained by parsing masked web-page screenshots into simplified HTML and fine-tuned on TextCaps (Sidorov et al., 2020: 28k Open Images photographs with five captions each that must mention the text in the image). At inference the processor (`Pix2StructImageProcessor`, `preprocessor_config.json`: `max_patches` 2048, **not** the VQA variant — no header is rendered and no font is involved) scales the image to fill at most 2048 patches while preserving aspect ratio, normalises it per image and flattens it into patch tokens; the decoder then generates the caption from the start token, or continues a caller-supplied prefix passed as decoder input ids (the upstream README's `A picture of` example). Nothing is trained or adapted here. What this repository adds is packaging: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `Pix2StructTextCapsPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, refusing a snapshot whose processor is the VQA variant), `caption` (input validation, an optional whitespace-collapsed prefix, greedy single-beam decoding under a caller-owned `max_new_tokens`, a `truncated` flag), `normalize_caption`, `caption_tokens`, `text_recall`, `keyword_hits`, `unigram_f1`, and the `validate_inputs` and `evaluation_report` stage helpers.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is single-sentence image captioning that quotes visible text: input one image (`PIL.Image.Image`, any mode, converted to RGB), an optional prefix (up to 128 characters) and a token budget; output one caption string, the number of tokens generated and whether the budget was exhausted. Envisioned applications are draft alt-text for images whose meaning depends on their text (signs, storefronts, product labels, posters, jerseys, screens) for later human editing, text-aware indexing and search over photo collections, and prototyping of reading-aware multimodal assistants — with the caption checked against the image by a human before it is shown to anyone who cannot see the image. The pipeline is an inference component and a zero-configuration baseline for text-aware captioning, not an OCR engine and not a certified describer for any image domain.

###### Primary Intended Users

Intended users are machine-learning engineers, computer-vision developers, and content or accessibility tooling developers integrating text-aware captioning into research prototypes or in-house tooling. A user is expected to understand that the output is *generated text* — it carries no probability, no correctness signal and no location in the image, and the model captions every image, including blank ones, with equal fluency and with plausible quoted text — that the model quotes only the text it deems caption-worthy (the smoke run quoted `STOP`, `Blue Fern Bakery` and `42` but not `OPEN` or `LIONS`) and returns no transcript, that a prefix is continued verbatim and sometimes mid-word (`A redoptical sign that says STOP.`), that the token budget is theirs to set, that the model was fine-tuned on photographs so drawings, documents and screenshots are distribution shifts, that greedy decoding is reproducible on a fixed device but GPU and CPU outputs need not match, and that caption quality can only be measured on reference captions they supply. Users who need a full OCR transcript, question answering, localisation or batch throughput are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no OCR transcript (the caption quotes some of the text, not all of it), no localisation or evidence region, no confidence, no abstention (the model cannot say "no text here"), no question answering (a separate checkpoint), no multi-sentence description, no batching (each image is a full encoder pass), no sampling or beam search (greedy, one beam), and no guarantee of colour, count or object accuracy — the smoke run called a green jersey blue.
2. **Input boundary:** `caption` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, a prefix that is not a string or is empty or longer than `MAX_PREFIX_CHARS = 128`, and budgets outside `[1, MAX_NEW_TOKENS = 64]` (`ValueError`/`TypeError`). Every image is scaled to fill at most 2048 patches of 16×16 px, so text that is only a few pixels tall at that scale is unlikely to be read, and a large blank margin costs patches.
3. **Input boundary:** the fine-tuning data is TextCaps — Open Images photographs containing legible English text (signs, packaging, screens, vehicles, clothing) with crowd-written captions. Flat drawings, rendered documents, screenshots of text-heavy pages, non-Latin scripts, handwriting and images without text fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded (the tutorial's cartoons are exactly such inputs, which is why their recall is sanity evidence). An image with no text still produces a caption that quotes invented text (see §Risks and harms).
4. **Decision boundary:** not for autonomous decisions that act on captions or on the text they quote — publishing alt-text unreviewed, reading prices, doses, warnings, licence plates or identity documents, content moderation, surveillance descriptions — without a human comparing the caption with the image, and a locally measured CIDEr/BLEU on the deployment's own reference-captioned images.

#### Factors

###### Groups

This pipeline is human-centric wherever the image contains people or text about them: TextCaps captions describe people in COCO's conventions (apparent gender, age, activity, dress) and quote text worn or held by them (jerseys, badges, name tags, placards), and the model reproduces both — including annotators' guesses — with no signal that it is guessing. Published audits of Open Images and COCO-style captions document gender-imbalanced activity associations and a skew towards Western, adult, lighter-skinned subjects; neither the upstream authors nor this repository audited caption accuracy or content by the depicted person's gender, age, skin tone, disability, dress or setting, nor text-reading accuracy by script, language, typeface or the text's cultural context. Non-human groups whose accuracy is unknown, not known to be equal: non-photographic images (the tutorial's cartoons; the model miscoloured a jersey and skipped two of five drawn strings), non-Latin and mixed-script signage, stylised or handwritten lettering, low-light and low-resolution captures, and non-Western products and storefronts. An operator whose images contain people or personal text is responsible for a fairness audit on their own image set, stratified by depicted group and text type, before relying on the output — and for deciding whether descriptions of people and their text are surfaced at all (see §Use cases).

###### Instrumentation

The upstream pretraining "instrument" is a web renderer (screenshots of pages paired with their HTML) and the fine-tuning instrument is Open Images photography (consumer cameras, Flickr uploads) with crowd-written captions. Inference images arrive from whatever produced them — a phone camera, a screenshot, a render, a scanner — and resolution, exposure, skew, compression, typeface and text size all change the visual evidence; the 2048-patch budget fixes the encoder's input size regardless of the source, so small type on a large image loses legibility while a large blank margin costs patches. The pipeline validates type, size and prefix length only; it cannot detect an unusual capture, a non-photographic image, or text too small to read. The synthetic tutorial scenes (flat Pillow shapes, Pillow's bundled font, no texture or lighting) are themselves a rendering instrument unlike any TextCaps photograph, which is why the smoke run's misses are recorded rather than treated as anomalies.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0`, `numpy==2.5.3`, `pillow==11.3.0`, float32 on CPU; CUDA is used automatically when visible (float32) but was not exercised for this card. Measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): load 5.58 s (verify of the 8-file, 1.13 GB snapshot included); three drawn scenes at the default budget, 2.78–3.35 s per caption (9–15 tokens); a 4096×4096 blank image 4.68 s — cost is dominated by the 2048-patch encoder pass per image and only weakly by the caption length. Data environment: the model assumes the image is a photograph containing legible English text worth mentioning; the synthetic tutorial scenes violate the first assumption on purpose (flat cartoons), which is where the recorded misses come from. Documents, screenshots, non-Latin scripts, tiny text and textless images violate it to degrees this repository did not measure, and the pipeline reports no signal when they do.

#### Metrics

###### Performance Measures

The pipeline reports no quality measure. The caption is generated text with no score, probability or correctness signal; `new_tokens` and `truncated` describe the generation, not its quality. TextCaps quality is conventionally measured with reference-based corpus metrics — CIDEr (the benchmark's primary), BLEU-4, METEOR, ROUGE-L, SPICE — which need several human-written references per image and a corpus; none is implemented here, and TextCaps is not bundled. The repository ships lighter helpers because they are what a caller can compute on their own labelled sample: `text_recall(caption, drawn_texts)` — the fraction of the distinct normalised tokens (lower-cased, punctuation removed) of the strings known to be in the image that appear in the caption, with `found` and `missing` listed — plus `keyword_hits` and a bag-of-words `unigram_f1` against reference captions. All are plumbing checks, stated as such. The public `evaluation_report(results, drawn_texts=None)` stage returns the report in machine-readable form: the mean `text_recall` plus one per-image entry (prediction, drawn strings, recall, found, missing) with the verdict `sample-sanity` when the drawn text is known, or the verdict `not-measurable` naming the labelled set that would be required when it is not. The upstream paper's TextCaps CIDEr for the base model (upstream-reported; not restated here because the hosted card gives no number) is not reproduced or claimed by this pipeline.

###### Decision thresholds

No score threshold exists in the model: it generates tokens until end-of-sequence or the budget and nothing is filtered or abstained. The decision parameters are the **token budget** `max_new_tokens`, default `DEFAULT_MAX_NEW_TOKENS = 30` (a sentence-sized budget chosen by this repository; the checkpoint's own `text_config.max_length` is 20 and the smoke captions needed 9–15 tokens including end-of-sequence, 21 for the blank-image invention) with ceiling `MAX_NEW_TOKENS = 64`, and the optional **prefix**, which the model continues verbatim — sometimes mid-word, and for the stop-sign drawing `A picture of` was followed by an immediate end-of-sequence — so the tutorial default is unconditional and a prefix is the caller's stylistic choice, not a quality control. A budget that is too small is reported, not hidden: `truncated` is true whenever `new_tokens` reaches it, and the caller should raise the budget and rerun. Decoding is greedy (`do_sample=False`, `num_beams=1`) with no temperature, beams or repetition penalty. A deployment owns choosing the budget and prefix and deciding how a caption — and the text it quotes — is verified against the image before it is used.

###### Approaches to uncertainty and variability

This repository reports no central metric value and therefore no dispersion: the smoke run records timings, token counts and the captions on three drawn scenes, not quality. Run-to-run variability comes only from floating-point kernel selection across CPU builds and accelerators; there is no sampling and no seed to set, so a fixed input on fixed hardware is repeatable, but because decoding is autoregressive a single differing token changes the rest of the sentence, and CPU and CUDA outputs need not match; the drawn scenes' bytes depend on the Pillow build's bundled font rendering. On the drawn scenes the model produced `A stop sign is on a pole.` (recall 1/1), `A blue sign that says Blue Fern Bakery.` (3/4, `OPEN` missing) and `A blue shirt with the number 42 on it.` (1/2, `LIONS` missing; the jersey is green) — three observations on flat cartoons, mean `text_recall` 0.75, not an estimate; on a blank white image it produced `A man is holding a bottle of alcohol and the bottle says 'the man's'.` and on uniform noise `A blue and white striped shirt with the number 10 on it.`, which is what an uncalibrated generator with no abstention looks like — it invents quoted text. A caller who needs a quality estimate must supply several reference captions per image and compute CIDEr/BLEU over a corpus or bootstrap resamples themselves; a caller who needs a confidence per caption, or per quoted string, has none from this model.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The upstream paper describes pretraining on 80M masked web-page screenshots paired with simplified HTML (from the C4 corpus's URLs) and fine-tuning on TextCaps, whose images come from Open Images (Flickr photographs under CC BY, containing legible text — shop signs, packaging, vehicles, clothing, screens — and frequently people) with crowd-written captions that quote that text; personal data in the fine-tuning corpus (names on badges and signs, licence plates, faces) is therefore present by construction, and web screenshots can contain more. Neither was audited here. This repository distributes code, tests, and documentation; it does not distribute the 1,129,177,976-byte `model.safetensors`, which is staged locally under `weights/pix2struct-textcaps-base/` and git-ignored, and it ships no sample photographs — the tutorial scenes are drawn in code with fictitious text. The operator must audit the images they submit for personal, proprietary, or otherwise restricted content; the pipeline performs no such check and will quote a name badge as readily as a shop sign.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Foreseeable but unintended sensitive uses — publishing captions as alt-text to blind or low-vision users where a misquoted price, dose, warning or direction misleads, reading licence plates, badges or identity documents from photographs, describing people and the text they wear in surveillance footage, labelling user-uploaded images for moderation — would be admissible only with human review of every caption and every quoted string against the image (the model invents quoted text when there is none and gives no signal), a locally measured reference-based score on the deployment's own captioned images stratified by depicted group and text type, a documented budget and prefix policy with `truncated` handling, an explicit policy on whether people and personal text are described at all, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, refuses a snapshot whose image processor is the VQA variant (which would render a header and fetch a font), and the smoke run loaded and captioned with `HF_HUB_OFFLINE=1`. The upstream `pytorch_model.bin` (pickle) is neither listed nor loaded. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot is refused before `torch` or `transformers` is imported.
- **Input integrity:** the public `validate_inputs(images, *, prefix, max_new_tokens)` stage applies exactly the checks `caption` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, the observed inputs, the checked prefix, the budget and the verdict; `validate_image` rejects non-PIL inputs and sides outside 16–4096 px; non-string, empty or over-long prefixes and out-of-range or boolean budgets are rejected; `caption` raises on a malformed runner result; `evaluation_report` rejects mismatched or empty drawn-text lists; `text_recall` rejects an empty or token-less drawn-text list.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; greedy single-beam decoding with no sampling; no font or header rendering on the model path; every result carries `model_id`, `model_revision`, the checked prefix, the budget, `new_tokens`, `truncated`, the device and the dtype.
- **Refusals:** no batching, no download without the explicit flag, no Hub access at inference time, no sampling, no pickle deserialisation, no attempt to guess whether the image contains text, and no filtering of caption content — that policy is the operator's to implement around the pipeline.
- No statistical mitigation (class balancing, subsampling) applies: no training happens in this repository.

###### Risks and harms

- **Invented quoted text:** the model has no abstention — a blank image yielded a bottle that "says 'the man's'" and noise a shirt with "the number 10" in the smoke run — so an image without text, or with text the model misreads, produces a fluent caption quoting text that is not there, with no signal; downstream consumers that trust the quoted string (alt-text, search indexes, price or label readers, LLM pipelines) inherit the error silently.
- **Selective and partial reading:** the model quotes the text it finds caption-worthy and omits the rest (`OPEN`, `LIONS` in the smoke run); a caller expecting a transcript gets a fraction of it, and near-miss readings of digits or names are stated with the same fluency as correct ones.
- **Hallucinated attributes:** colours, objects and scene elements that are not there (a green jersey called blue) accompany the quoted text; only reference-based evaluation on the deployment's images shows the rate, and the tutorial measures none.
- **Descriptions of people and personal text:** names, numbers and slogans worn or held by people are quoted, and people are described in COCO's conventions (apparent gender, age); misgendering, misattributed text and stereotyped associations are foreseeable and can cause direct harm when surfaced.
- **Prefix steering:** a conditional caption is partly the caller's sentence; a leading prefix makes the model complete it, sometimes mid-word.
- **Automation bias:** a grammatical sentence with a confidently quoted string invites trust that generated text has not earned.
- **Truncation:** a caption longer than the budget is cut (reported via `truncated`); a caller who ignores the flag ships a partial sentence, possibly mid-quote.
- **Bias amplification:** any image population, script or typeface TextCaps under-represents is reproduced as uneven reading and caption quality, undetected because no per-group evaluation exists.
- **Resource use:** a 1.13 GB model and ~2.8–3.4 s per image on the reference CPU with a 2048-patch encoder pass per image; an image-heavy workload scales linearly, and the CUDA path was not measured.

###### Use cases

Prohibited even where the model would work: captioning images of people in order to infer or record protected characteristics (race, ethnicity, religion, health, disability, sexual orientation), to identify, track, profile or surveil individuals — including by reading names, badges, licence plates or other identifying text — or to make or support decisions in employment, housing, credit, insurance, education, healthcare access, law enforcement or immigration; processing images the operator has no right to process, including intimate imagery, private documents and licence-restricted material; publishing captions or the text they quote as verified facts, evidence or alt-text without human review; steering the model with prefixes to produce defamatory, sexual or demeaning descriptions of real people; and any use that violates the upstream Apache-2.0 licence terms, the terms of the deployment that runs the pipeline, or the consent and data-protection obligations attached to the images processed. Autonomous high-consequence actions triggered by unreviewed captions are prohibited by the intended-use contract above.

## Input/output contract

- `Pix2StructTextCapsPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `caption(image, *, prefix=None, max_new_tokens=30) -> dict` with keys `caption` (stripped decoded text; the prefix is echoed first when given), `prefix` (whitespace-collapsed or `None`), `image_size`, `new_tokens` (tokens generated after the prefix, end-of-sequence included), `truncated`, `generation` (`max_new_tokens`, `do_sample` false, `decoding` greedy), `device`, `dtype`, `source`, `model_id`, `model_revision`.
- `normalize_caption(text) -> str`; `caption_tokens(text) -> list[str]`; `text_recall(caption, drawn_texts) -> dict` (`recall`, `found`, `missing`, `n_expected`); `keyword_hits(caption, keywords) -> dict[str, bool]`; `unigram_f1(prediction, references) -> float`.
- Ceilings and constants: `MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`, `MAX_PREFIX_CHARS = 128`, `MAX_NEW_TOKENS = 64`, `DEFAULT_MAX_NEW_TOKENS = 30`, `DECODING = "greedy"`, `MAX_PATCHES = 2048`, `INPUT_SCHEMA`.
- `validate_inputs(images, *, prefix, max_new_tokens, names) -> dict`; `evaluation_report(results, drawn_texts=None, *, sample_kind) -> dict` where `drawn_texts` holds one sequence of strings known to be in each image; `verify_snapshot(path=None) -> dict`; `stage_missing_files(path=None, *, allow_download=False, downloader=None) -> list[str]`.
