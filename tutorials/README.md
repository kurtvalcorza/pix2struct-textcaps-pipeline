## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/pix2struct_textcaps_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True` and `trust_remote_code=False` through `Pix2StructForConditionalGeneration`/`Pix2StructProcessor`, refusing a VQA-variant processor. The upstream `pytorch_model.bin` is not listed and not used; no header is rendered and no font is fetched (the processor is not the VQA variant), so the notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/pix2struct_textcaps_input_manifest.json` with the schema (patch budget, decoding rule), the ceilings, each input's observed mode and size, the checked prefix, the budget, the verdict, and one recorded rejection finding from the tiny-image probe; `evaluation_report` writes `outputs/pix2struct_textcaps_evaluation_report.json` — `sample-sanity` with the mean `text_recall` and one entry per image (prediction, drawn strings, recall, found, missing) on the synthetic scenes; `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is three deterministic cartoon scenes drawn in code with text rendered in Pillow's bundled font — the same drawings the smoke run used; `text_recall` against strings you drew yourself is sanity evidence for the input contract, patch extraction, forward pass, decoding and the OCR-free reading path, not a TextCaps metric. **Two of the five drawn strings are recorded misses** (the smoke run did not quote `OPEN` or `LIONS`, and called the green jersey blue); they stay in the scored set so the report shows what partial recall looks like. The image digests depend on the Pillow build's bundled font rendering and are printed, not asserted.
- Score semantics (UNC1–UNC4): the caption is generated text with no score, probability or correctness signal; the notebook says so before the first caption and again in the interpretation section, and states that the model captions textless images with invented quoted text (blank → a bottle "that says 'the man's'" in the smoke run). The token budget and the prefix are caller-owned request parameters exposed as `# @param` values (defaults `DEFAULT_MAX_NEW_TOKENS = 30`, empty prefix = unconditional; the prefix can be continued mid-word, which the notebook shows) and passed explicitly on every `caption` call; `truncated` is surfaced and explained. The notebook performs no validation of its own — images, prefix and budget are checked only by the pipeline's `validate_inputs`/`caption` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MAX_PREFIX_CHARS` (128), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (30) and `DECODING` are printed before the model runs.
- CPU is documented as adequate (card-measured 5.6 s load, 2.8–3.4 s per caption on the drawn scenes; 4.7 s on a 4096×4096 blank image); the notebook states that cost is per image and that GPU output need not match CPU output token-for-token.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
